# Tempo Delay Spotter (iPhone Shortcuts)

Delay Spotter is Tempo's **on-device signal filter** (spec §15.9) for the Clawback UK rail skill,
built entirely in Apple's Shortcuts app. No native app, no paid developer account and no Apple
review are needed.

When a delay text or email arrives, a Shortcuts automation runs it through a handful of regexes
**on the phone**. It pulls out the departure time, the two stations and the travel date, then
starts a Clawback mission with `POST /missions`. **The message itself never leaves the phone.**
The Gateway receives only this:

```json
{"user_id": "u_amir", "display_name": "Amir", "phone": "",
 "origin_crs": "OXF", "destination_crs": "PAD", "travel_date": "2026-10-23", "departure": "08:12",
 "fare_gbp": "28.40", "time_value_gbp_h": "18"}
```

The Gateway looks up the official delay itself (HSP/RTT, or recorded journeys in replay mode),
works out the refund and asks for consent. The phone then shows the Gateway's answer:

> **Tempo**: 38 min late → 50% of £28.40 under GWR DR15 (…). I claim online for you: £14.20 for 0 min
> of your time (…). Shall I claim £14.20 for you?

## Before you start (5 min)

You need:

- An iPhone on **iOS 26 or 27**. Run Immediately exists from iOS 17, but the steps below are
  written for 26 and 27.
- A **Gateway URL the phone can reach** and its **bearer token** (`TEMPO_API_TOKEN`). See
  [How the phone reaches the Gateway](#how-the-phone-reaches-the-gateway). For a demo: start a
  replay Gateway and a Cloudflare tunnel, and use a fresh token made only for the demo.
- Your usual **fare** (for example `28.40`), a **user id** and the **name** Tempo should use.
- This README open where you can copy from it. Copy each regex rather than typing it.

**Tip:** building is much faster in **Shortcuts on a Mac** with copy and paste. The finished
shortcut syncs to your iPhone if iCloud Sync is on (iPhone: Settings → Apps → Shortcuts →
iCloud Sync). Automations don't sync: always create those on the iPhone.

## Fast path: import the signed file (2 min)

[`Tempo-Delay-Spotter.shortcut`](Tempo-Delay-Spotter.shortcut) is the shortcut below, generated by
[`build_shortcut.py`](build_shortcut.py) and signed so that anyone can import it.
**Experimental:** it hasn't been imported on a device yet. If it won't import, build it by hand.

1. AirDrop the file to the iPhone (or open it from Files) and tap **Add Shortcut**.
2. Open the shortcut and find **Get Contents of URL** near the end. Replace the placeholders:
   the URL, `CHANGE-ME` in the `Authorization` header, and `user_id`, `display_name`, `phone`
   (optional), `fare_gbp` and `time_value_gbp_h` in the JSON body.
3. Change the **Stations** dictionary at the top to your commute (see Block 1).
4. Carry on at [Add the automations](#add-the-automations-5-min).

The file holds placeholders only. To make a copy with your values already in it, run
`build_shortcut.py --url … --token …`. **Don't share that copy:** it contains your token.

## Build the shortcut by hand (about 20 min)

In Shortcuts, tap **+** to make a new shortcut and name it **Tempo Delay Spotter**. The core
shortcut takes text as its input. The automations later pass the message to it, and for tests it
reads the clipboard.

### The finished shortcut, at a glance

Check your work against this list. Shortcuts adds the grey **Otherwise** and **End If** lines by
itself when you add an **If**.

```text
 1  Dictionary  (Stations: name → CRS)
 2  Set variable AlertText to Shortcut Input
 3  Match <signal> in AlertText
    If Matches does not have any value → Stop This Shortcut → End If
 4  Match <short_delay> in AlertText
    If Matches has any value → Stop This Shortcut → End If
 5  Match <departure> in AlertText → Get Group at Index 1 → Replace "." with ":" → Set variable Departure
 6  Match <stations> in AlertText → Get Group at Index 1 → Set variable From
                                 → Get Group at Index 2 (of Matches) → Set variable To
    Get Value for From in Dictionary → Set variable OriginCRS
    Get Value for To in Dictionary → Set variable DestCRS
 7  Format Current Date as yyyy-MM-dd → Set variable TravelDate
    Match <date> in AlertText
    If Matches has any value → Get Group at Index 1 → Format Date as yyyy-MM-dd → Set variable TravelDate → End If
 8  Text "OriginCRS DestCRS Departure TravelDate" → Match <check> in Text
    If Matches does not have any value → Show Notification "couldn't read…" → Stop This Shortcut → End If
 9  Get Contents of URL  (POST JSON to /missions, bearer token)
10  Get Value for "message" in Contents of URL
    If Dictionary Value has any value → Show Notification (it) → Otherwise → Show Notification (Contents of URL) → End If
```

### How to work in the editor

- Add an action with the **search field** at the bottom (iPhone) or the action library (Mac).
  New actions land at the **end**. Drag them into place, for example between an **If** and its
  **Otherwise**.
- To put a variable in a field, tap the field and pick it from the bar above the keyboard, or
  tap **Select Variable**. *Matches*, *Dictionary*, *Contents of URL* and so on are earlier
  actions' outputs. Named variables (AlertText, Departure…) appear once you've set them.
- Some options are hidden until you tap the action's **›** chevron, such as **Case Sensitive**
  on Match Text and the method on Get Contents of URL.
- A new **Get Group at Index** or **Get Dictionary Value** takes the previous action's output by
  default. Each block below says which input to choose instead.

### Shortcut settings

Open the shortcut's details (the **ⓘ** button; on a Mac, the sidebar):

- Turn on **Show in Share Sheet** and make it receive **Text**.
- The top of the shortcut now reads *Receive Text input from Share Sheet*. Set **If there's no
  input** to **Get Clipboard**. This lets you test it by copying a sample alert and tapping run.

### Block 1: Stations

Add a **Dictionary** action. Add one **Text** item per station: the key is the name as your
operator writes it, the value its CRS code. Keys must match exactly (case too), so add any
variant spellings. The starter set is in [`fixtures/stations.yaml`](fixtures/stations.yaml).
The demo needs at least these:

| Key | Value |
|---|---|
| `Oxford` | `OXF` |
| `London Paddington` | `PAD` |
| `Paddington` | `PAD` |
| `Reading` | `RDG` |
| `London Marylebone` | `MYB` |

A station that isn't here stops the shortcut on the phone, with a notification. Nothing is sent.

### Block 2: The alert text

Add **Set Variable**. Name it `AlertText` and set it to **Shortcut Input**. The optional Use
Model step replaces this block.

### Block 3: Is it about a delay?

1. Add **Match Text**. Paste this into the pattern, and set the text to **AlertText**:
   <!-- regex: signal -->
   ```text
   (?i)\b(?:delay(?:ed|s)?|cancel(?:l?ed|lation)|running late|disruption)\b
   ```
2. Add **If**: input **Matches**, condition **does not have any value**.
3. Add **Stop This Shortcut** and drag it inside the If.

### Block 4: Too short to claim?

Delay Repay starts at 15 minutes. This regex matches only when the first delay in the text is
under 15 minutes and the text mentions neither a cancellation nor hours. Delay minutes are used
only here, on the phone. The Gateway takes the official delay from rail data.

1. **Match Text** on **AlertText**:
   <!-- regex: short_delay -->
   ```text
   (?i)^(?![\s\S]*\bcancel)(?![\s\S]*\b\d{1,2}\s?(?:hours?|hrs?)\b)(?:(?!\b\d{1,3}\s?(?:mins?|minutes)\b)[\s\S])*\b(\d|1[0-4])\s?(?:mins?|minutes)\b
   ```
2. **If** **Matches** **has any value** → **Stop This Shortcut** inside it.

For a DR30 operator (claims from 30 minutes), change `(\d|1[0-4])` to `(\d|[12]\d)`.

### Block 5: Departure time

The first 24-hour time in the text, `08:12` or `08.12`.

1. **Match Text** on **AlertText**. Leave **Case Sensitive** on.
   <!-- regex: departure -->
   ```text
   ^[\s\S]*?(?<![\d.:/])((?:[01]\d|2[0-3])[:.][0-5]\d)(?![.:/]?\d)
   ```
2. **Get Group from Matched Text** (it shows as *Get Group at Index 1 in Matches*). Index `1`.
3. **Replace Text**: find `.`, replace with `:`, in the group's **Text**.
4. **Set Variable** `Departure` to **Updated Text**.

### Block 6: Stations to CRS codes

1. **Match Text** on **AlertText**. **Case Sensitive must be on**, because station names are
   found by their capital letters.
   <!-- regex: stations -->
   ```text
   ^[\s\S]*?\b(?!(?:The|Your|This|Our|An?|Sorry|Update|Alert|Delayed|Cancelled|Service|Train|Today's|Tonight's)\b)([A-Z][A-Za-z'’]*(?:-[A-Za-z]+)*(?: (?:[A-Z][A-Za-z'’]*(?:-[A-Za-z]+)*|&))*)\s+(?:to|-|–|—|→)\s+([A-Z][A-Za-z'’]*(?:-[A-Za-z]+)*(?: (?:[A-Z][A-Za-z'’]*(?:-[A-Za-z]+)*|&))*)
   ```
2. **Get Group at Index** `1` in **Matches** → **Set Variable** `From`.
3. **Get Group at Index** `2`. Tap its input and choose this block's **Matches**, not the
   previous group. → **Set Variable** `To`.
4. **Get Dictionary Value**: *Get Value for* **From** *in* **Dictionary** (Block 1's output, not
   the previous action's) → **Set Variable** `OriginCRS`.
5. The same again for **To** → **Set Variable** `DestCRS`.

It finds "Oxford to London Paddington", "Oxford - London Paddington", "Reading → Birmingham New
Street" and names such as "Haddenham & Thame Parkway" or "Stratford-upon-Avon". It skips
opening words like "The" and "Your".

### Block 7: Travel date

Most texts have no date, so the default is the day the message arrived. Emails and reminders
often say "on Fri 23 Oct". **Format Date** reads that as the nearest 23 October, so no year is
needed (tested with macOS's date detector; **check on device**).

1. **Format Date**: date **Current Date**, Date Format **Custom**, format string
   `yyyy-MM-dd`, Time Format **None**. → **Set Variable** `TravelDate`.
2. **Match Text** on **AlertText**:
   <!-- regex: date -->
   ```text
   (?i)^[\s\S]*?\b(\d{1,2}(?:st|nd|rd|th)?\s+(?:Jan|Feb|Mar|Apr|May|Jun|Jul|Aug|Sep|Oct|Nov|Dec)[a-z]*(?:\s+\d{4})?)\b
   ```
3. **If** **Matches** **has any value**, and inside it:
   **Get Group at Index** `1` in **Matches** → **Format Date** on that group (Custom,
   `yyyy-MM-dd`) → **Set Variable** `TravelDate`.

### Block 8: Check before anything leaves the phone

1. **Text**: insert the variables with single spaces between them:
   `OriginCRS DestCRS Departure TravelDate`.
2. **Match Text** on that **Text**, Case Sensitive on:
   <!-- regex: check -->
   ```text
   ^[A-Z]{3} [A-Z]{3} (?:[01]\d|2[0-3]):[0-5]\d \d{4}-\d{2}-\d{2}$
   ```
3. **If** **Matches** **does not have any value**, and inside it:
   - **Show Notification**, title `Tempo Delay Spotter`, body:
     `Spotted a delay but couldn't read the journey (Departure From to To). Add missing
     stations to Stations. Nothing was sent.` Insert the three variables where named.
   - **Stop This Shortcut**.

### Block 9: Start a Clawback mission

Add **Get Contents of URL** and tap **›**:

| Setting | Value |
|---|---|
| URL | `https://<your-tunnel>/missions` (see [below](#how-the-phone-reaches-the-gateway)) |
| Method | `POST` |
| Headers | `Authorization` = `Bearer <your token>` |
| Request Body | `JSON` |

Under **JSON**, add these fields (**Add new field → Text**). Type the first five once, the rest are
variables:

| Key | Value |
|---|---|
| `user_id` | your user id, e.g. `u_amir` |
| `display_name` | e.g. `Amir` |
| `phone` | optional: your mobile, so Tempo can text you and you can reply YES/NO. Leave empty otherwise. The Gateway keeps only its hash. |
| `fare_gbp` | your usual fare, e.g. `28.40` |
| `time_value_gbp_h` | what an hour of your time is worth, e.g. `18` |
| `origin_crs` | variable **OriginCRS** |
| `destination_crs` | variable **DestCRS** |
| `travel_date` | variable **TravelDate** |
| `departure` | variable **Departure** |

These are the `StartMission` fields in
[`apps/gateway/src/tempo_gateway/missions.py`](../gateway/src/tempo_gateway/missions.py).

### Block 10: Tell me

1. **Get Dictionary Value**: *Get Value for* `message` *in* **Contents of URL**.
2. **If** **Dictionary Value** **has any value** → **Show Notification**, title `Tempo`, body
   **Dictionary Value**.
3. In **Otherwise** → **Show Notification**, title `Tempo couldn't start a claim`, body
   **Contents of URL**. A wrong token shows `{"detail":"a valid bearer token is required"}`.

The message is long. Long-press the notification to read all of it: the amount comes at the end.

### Optional: privacy log (1 action)

The spec asks for a log on each device of *what left this phone, when, and for which skill*.
After Block 9, add **Append to Text File**: text
`Current Date · clawback.uk-rail-delay-repay · OriginCRS DestCRS TravelDate Departure`, file
`Shortcuts/Tempo privacy log.txt` in iCloud Drive. Turn on **Make New Line**.

## Optional: Use Model on Apple Intelligence iPhones (5 min)

On an Apple Intelligence iPhone, the on-device model can rewrite messy alerts into one tidy line
before the regexes run. This needs iPhone 15 Pro or later, Apple Intelligence turned on, and a
supported language: English (UK) is fine. The regexes stay as the fallback. They read the
model's line first, and anything the model left out is found in the original text after it.
**Don't add this on other iPhones.**

Replace **Block 2** with:

1. **Use Model**. Choose **On-Device**: *Private Cloud Compute* and *ChatGPT* send the text off
   the phone. Output: **Text**. Prompt (insert **Shortcut Input** at the end):
   ```text
   Rewrite this UK train alert as one line in exactly this format:
   HH:MM Origin to Destination, N min late, D Mon
   Use the scheduled departure time in 24-hour form and the station names exactly as written.
   Write "cancelled" instead of "N min late" if the train was cancelled. Leave out any part the
   alert doesn't give. Reply with the line only.
   Alert: [Shortcut Input]
   ```
2. **Text**: the model's **Response**, a new line, then **Shortcut Input**.
3. **Set Variable** `AlertText` to that **Text**.

Example: for *"Your train from Oxford (08:12) to London Paddington is delayed by 38 minutes"*,
the regexes alone can't find the stations (fixture `trainline-push-0812`). With the model's
line `08:12 Oxford to London Paddington, 38 min late` in front, they can. The script replays this
with the hand-written `model_line` in the fixtures (`--model`). It can't run Apple's model itself.

## Add the automations (5 min)

Each automation is a small wrapper that passes the message to **Tempo Delay Spotter**. The core
shortcut stays testable, and the same core serves text, email and (on iOS 27) notification
triggers.

### Text messages

**Why not filter on the sender?** The trigger's *Sender* field offers only your Contacts.
Operators text from short codes or names such as "GWR", which usually aren't contacts. So
trigger on the words instead, and let Block 3 do the filtering. Apple's rule is that all the
criteria you set must match. If you've saved your operator's alert number as a contact, a
Sender-only trigger works too.

**iOS 27** (automations are now triggers at the top of a shortcut; **check on device**):

1. Make a new shortcut called **Delay Spotter: Messages**. Add an action from the
   **Automation** category: **Message**, *When I receive a message where… Message contains*
   `delay`.
2. Add a second Message trigger with `cancel`. iOS 27 lets you stack triggers.
3. Tap the arrow next to each trigger: **Confirm Before Run** off. Under **ⓘ → Privacy**,
   **Allow Running When Locked** on.
4. Add **Run Shortcut** → **Tempo Delay Spotter**, with input **Message** (the trigger's variable).
5. Check the automation is switched on in **Library → Automation**.

**iOS 26:**

1. **Automation** tab → **+** → **Message**.
2. **Message Contains**: `delay`. Leave **Sender** empty.
3. Choose **Run Immediately** → **Next** → **New Blank Automation**.
4. Add **Run Shortcut** → **Tempo Delay Spotter**. Tap **›** and set **Input** to **Shortcut Input**.
5. Repeat for `cancel`. On iOS 26 each automation takes one phrase.

Whether *Message contains* ignores case isn't documented. Test with a text that starts
"Delayed". If it doesn't fire, add triggers for `Delay` and `Cancel` too **(check on device)**.

### Emails (Trainline and operator emails)

This works with accounts in Apple's **Mail** app only, not the Gmail or Outlook apps.

1. Make a trigger (iOS 27: Automation category → **Email**; iOS 26: Automation tab → **+** →
   **Email**). Pick one:
   - **Sender**: type the address your alert emails come from (check an old one in Mail), or
   - **Subject Contains**: `delay`, plus a second trigger for `cancel`.
2. **Run Immediately** (iOS 26) or **Confirm Before Run** off (iOS 27).
3. Add a **Text** action: the email's **Subject**, a new line, then its **Body**. Insert
   **Shortcut Input** (iOS 26) or **Email** (iOS 27), tap the token and pick *Subject*. Do the
   same for *Body*. If your phone shows *Content* rather than *Body*, use that. If it offers no
   properties, insert the input as it is **(check on device)**.
4. **Run Shortcut** → **Tempo Delay Spotter** with that **Text** as input.

### App notifications (iOS 27 only, untested)

The Message trigger never fires for train apps' **push notifications**. iOS 27 adds a separate
**Notification** trigger, reported to fire on a chosen app's notifications and filter on their
title, subtitle or message. That could cover the Trainline and National Rail apps. The same
wrapper pattern applies: trigger → **Text** (*Notification* title, new line, body) →
**Run Shortcut**. App alerts often leave out where the train started ("Your 08:12 to London
Paddington is delayed"). Then Block 8 says it couldn't read the journey, and nothing is sent.

## Test it

1. **The shortcut on its own.** Copy this demo text, then tap **Tempo Delay Spotter** in the
   Shortcuts app. With no input, it reads the clipboard.
   ```text
   GWR: We're sorry, the 08:12 Oxford to London Paddington on Fri 23 Oct is delayed by approximately 38 minutes.
   ```
   With a replay Gateway, the notification should read *"38 min late → 50% of £28.40 under GWR
   DR15 … Shall I claim £14.20 for you?"* The mission appears in Mission Control as
   `awaiting_consent`. The text names the date because replay mode only knows journeys on 22
   and 23 October; a real alert sent the same day doesn't need one. The script gives the same
   result:
   `uv run python apps/shortcuts/delay_spotter.py try "<the text>" --send --in-process`.
2. **The quiet paths.** A 9-minute delay (`gwr-sms-0912-short`) should do nothing. An alert with
   a station that isn't in your dictionary (`crosscountry-sms-0905-unknown-station`) should show
   "couldn't read the journey". Neither sends anything.
3. **The automation.** Ask a teammate to text you the demo text. A text from your own Apple ID
   may not count as received. Expect iOS's own banner that the automation ran, then Tempo's
   notification.
4. **Locked phone.** Lock the phone and repeat. Locked-phone runs must be tested on a real
   device **(check on device)**. Also check that a phone that has restarted but not yet been
   unlocked behaves as you expect.
5. **Approve.** Say yes in Mission Control (`POST /approvals/{request_id}`). In live mode with
   Twilio and `phone` set, you can also reply YES by SMS.

## How the phone reaches the Gateway

`uv run tempo-gateway` listens on `127.0.0.1:8000`, so only the laptop can reach it. Choose one:

| Way | How | URL in the shortcut | Notes |
|---|---|---|---|
| **Cloudflare quick tunnel** (recommended for the demo) | `brew install cloudflared`, then `cloudflared tunnel --url http://127.0.0.1:8000` | `https://<random>.trycloudflare.com/missions` | HTTPS, works over 4G and on Wi-Fi that keeps devices apart, no account needed. The URL changes on every run, so update the shortcut. |
| **ngrok** | `ngrok http 8000` (free account and authtoken) | `https://<id>.ngrok-free.app/missions` | If you get ngrok's warning page rather than JSON, add a header `ngrok-skip-browser-warning: 1`. |
| **Same Wi-Fi or Personal Hotspot** | `uv run uvicorn --factory tempo_gateway.main:build --host 0.0.0.0 --port 8000`. This is the same app without the 30-second Watchdog loop, so use `POST /scheduler/tick` to fire timers. Find the laptop's address with `ipconfig getifaddr en0`. | `http://<laptop-ip>:8000/missions` | Venue Wi-Fi often stops devices reaching each other. If so, join the laptop to the iPhone's Personal Hotspot (addresses `172.20.10.x`). Allow Shortcuts **Local Network** access if iOS asks. Plain HTTP: the token crosses the network unencrypted. |

Check from the phone first: open `https://<your-url>/health` in Safari. It should answer
`{"status":"ok","mode":"replay",…}`.

### Keep the token scoped for the demo

Today the Gateway has **one** bearer token, `TEMPO_API_TOKEN`. Whoever holds it can list every
mission, **approve consent asks** (`POST /approvals`), stop missions, and read and delete
memories. A tunnel makes the Gateway public, so the token is the only lock. For the demo:

- **Make a fresh demo-only token:** `python3 -c "import secrets; print(secrets.token_urlsafe(24))"`.
  Set it as `TEMPO_API_TOKEN` on a **replay-mode** Gateway with no real keys, and use it nowhere
  else.
- Prefer the **HTTPS tunnel** to plain HTTP on shared Wi-Fi.
- **Don't share the filled-in shortcut** (iCloud link, AirDrop, a file in git). It carries the
  token. The signed file in this folder holds placeholders only.
- After the demo, **stop the tunnel and change the token**.
- The real fix needs a Gateway change: a token that can only start rail missions. See the
  [proposal](#proposal-post-signalsrail-gateway-change-not-made).

## The replay script

[`delay_spotter.py`](delay_spotter.py) applies the shortcut's regexes and Stations dictionary to
each fixture, block for block, and sends the identical POST. Run it from the repo root:

```bash
uv run python apps/shortcuts/delay_spotter.py check --icu
```

```bash
uv run python apps/shortcuts/delay_spotter.py send --in-process
```

```bash
TEMPO_API_TOKEN=<token> GATEWAY_URL=http://127.0.0.1:8000 uv run python apps/shortcuts/delay_spotter.py send gwr-sms-0812-delayed
```

- `check`: every fixture through the extraction, compared with `expect` in
  [`fixtures/alerts.yaml`](fixtures/alerts.yaml). It also checks that the regexes in this README
  are identical to [`fixtures/patterns.yaml`](fixtures/patterns.yaml). `--icu` (macOS) runs every
  pattern through `NSRegularExpression`, the engine Shortcuts uses, and Apple's date detector,
  and fails on any difference.
- `send`: POSTs what the shortcut would send and checks the Gateway's answer against
  `expect.gateway`. `--in-process` boots the replay Gateway inside the script. Without it, the
  script talks to a running Gateway at `GATEWAY_URL` with `TEMPO_API_TOKEN`. `--model` uses the
  fixtures' simulated Use Model lines.
- `payload`: prints the JSON each fixture would send, which is exactly what leaves the phone.
- `try "<text>"`: what the phone would make of any alert. Paste a real one from your operator
  to see whether the regexes and your Stations cope. Add `--send`, and `--received` to set the
  arrival time.

What the replay Gateway answers (`send`):

| Fixture | On the phone | Replay Gateway |
|---|---|---|
| `gwr-sms-0812-delayed` | sends OXF→PAD 08:12, 23 Oct | `awaiting_consent`: "Shall I claim £14.20 for you?" |
| `nre-sms-0758-delayed` | sends OXF→PAD 07:58, 22 Oct | `awaiting_consent`: £28.40 (64 min, 100%) |
| `trainline-email-1742-cancelled` | sends OXF→PAD 17:42, 23 Oct | `awaiting_consent`: £28.40 (cancelled counts as the top band) |
| `trainline-email-0812-claim-reminder` | date taken from the text (arrived 25 Oct) | `awaiting_consent`: £14.20 |
| `trainline-push-0812` + Use Model | regexes alone can't read it; the model's line fixes that | `awaiting_consent`: £14.20 |
| `chiltern-sms-0744-delayed`, `gwr-email-1821-hours` | sent | `declined`: "I couldn't find that train in the rail records" (not recorded in replay mode) |
| `gwr-sms-0912-short` | 9 min: stops, nothing sent | n/a |
| `crosscountry-sms-0905-unknown-station`, `nre-sms-disruption` | can't read the journey: one notification, nothing sent | n/a |

[`build_shortcut.py`](build_shortcut.py) regenerates and re-signs the `.shortcut` file from the
same YAML (`--unsigned` writes just the plist).

## Limits

- **Messages and Mail only.** The Message trigger fires for texts in Messages (SMS, iMessage,
  RCS). The Email trigger fires only for accounts in Apple Mail. Neither fires for train apps'
  push notifications. iOS 27's Notification trigger might (untested).
- **There's always a banner.** Run Immediately still shows iOS's own notification each time an
  automation runs. It can't be turned off.
- **Locked phone and restarts.** Reliability while locked, and before the first unlock after a
  restart, must be tested on a real device. The POST also needs a network connection; with
  none, the run fails with an error notification and nothing is retried.
- **Use Model** needs an Apple Intelligence iPhone (iPhone 15 Pro or later) with Apple
  Intelligence on, in a supported language. Only the **On-Device** model keeps the text on the
  phone.
- **The regexes were tested on synthetic samples.** Real operator wording varies. Try real
  alerts with `try` and add station spellings to the dictionary. Times must be 24-hour `HH:MM`
  or `HH.MM` (not `0812`). Stations must be written "A to B" or "A - B". Names with digits
  (such as "Heathrow Terminal 5") aren't supported.
- **Travel date.** With no date in the text, it's the day the message arrived. An alert for a
  train just before midnight that arrives after midnight gets the wrong day.
- **Duplicates.** The same train reported by text *and* by email starts two missions. The
  Gateway doesn't de-duplicate yet (see the proposal).
- **Replay mode** knows only four recorded journeys: Oxford → London Paddington at 07:58 on
  22 Oct, and at 08:12, 09:12 and 17:42 on 23 Oct.
- **Long notification.** The Gateway's consent message is about 250 characters, and the amount
  comes last.

## Proposal: `POST /signals/rail` (Gateway change, not made)

This was not built here: another session owns `apps/gateway`. The current `POST /missions` works
for the demo. For real users, a narrow endpoint would be safer and simpler:

```http
POST /signals/rail
Authorization: Bearer <per-device signal token>

{"device_id": "iphone-amir", "skill": "clawback.uk-rail-delay-repay",
 "origin": "Oxford", "destination": "London Paddington",
 "departure": "08:12", "travel_date": "2026-10-23", "cancelled": false}
```

- **A scoped token.** A per-device `signal` token that can only start Clawback rail missions for
  the one user it's bound to. It can't list, approve, stop, or read memories, and it can be
  revoked on its own. Losing a phone then costs nothing.
- **Names to CRS codes on the server.** The Gateway maps station names to CRS codes using the
  full station list (about 2,600 stations) and known variant spellings. No per-phone Stations
  dictionary, and an unknown name gets a clear "which station did you mean?" reply.
- **Even less leaves the phone.** `user_id`, `display_name`, the fare and the time value come
  from the user's profile on the server, not from every request.
- **Idempotent.** Key on (user, origin, destination, date, departure), so the same train from
  text and email returns the existing mission.
- **A short reply.** A `say` field of 100 characters or fewer for the notification, such as
  "GWR owes you about £14.20. Reply YES to claim." The full message stays in Mission Control.
- **Rate limits and a server-side privacy log** for each device token, matching the phone's
  log (spec §15.9).

## Tempo Scam Spotter (Scam Shield on an iPhone)

iOS gives no app a way to read other apps' notifications, so an iPhone cannot run Scam Shield's
filter in the background the way the Android node does (`apps/android-signal`). What it can do,
with no native app, no paid developer account and no review, is **Tempo Scam Spotter**
(`build_scam_spotter.py`, `Tempo-Scam-Spotter.shortcut`, signed for anyone):

- **Share sheet.** On any text, email or web page: Share → *Tempo Scam Spotter*. The message goes
  to the Gateway's `POST /scam/check` (the same code that answers the Android node, the SMS `CHECK`
  word and the voice line) and the phone **speaks the answer** with its own voice (Speak Text,
  offline), slowly, in the language set at build time (`--language hi`, `pa`, `pl`, `ur`, `cy`),
  then shows it as a notification. For a likely scam that is *"Do not touch that message. It is a
  trick trying to take your money."*, then why, then *"Ring the firm on a number you already know."*
- **Automation.** Shortcuts → Automation → **Message** → *Message Contains* `http` → *Run
  Immediately* → **Run Shortcut** → *Tempo Scam Spotter* with the message as input. Every text
  with a link is then checked as it arrives; add a second automation for `www.` **(check on
  device)**. Apple's Message trigger does not fire for other apps' notifications, so WhatsApp and
  email need the share sheet.
- **Honesty.** Unlike the Android node, which sends only four derived fields, the shortcut sends
  the **message text** to the Gateway: Shortcuts cannot run the model or the link rules itself. The
  Gateway keeps nothing but the verdict (docs/scam-shield.md §5.3). If that is not acceptable, use
  the share sheet only for messages you are already unsure about.

Build it with your Gateway and token (the file then holds a real token: don't share or commit it):

```bash
uv run python apps/shortcuts/build_scam_spotter.py --url https://YOUR-GATEWAY/scam/check --token YOUR-TOKEN --language en
```
